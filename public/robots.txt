# ⚠️ robots.txt bir GÜVENLİK SINIRI DEĞİLDİR — dürüst crawler'lara verilen bir ricadır.
#    Asıl sınır `proxy.ts` + `requireStaff()` + RLS. Buradaki amaç:
#    (a) özel alanların arama sonuçlarında görünmemesi,
#    (b) crawler bütçesinin herkese açık sayfalara harcanması.
#    Bu yüzden disallow listesi "gizlensin" diye değil, "indekslenmesin" diye var.
#
# KURAL: yeni bir özel alan (panel benzeri) eklerken DÖRT bloğu da güncelle
#        (*, GoogleBot, GPTBot, ClaudeBot).
#        Listeler bilinçli olarak birebir aynı; farklılaşırlarsa bu bir hatadır.
#
# 🚨 10 AĞU 2026 — `Allow: /api/ilanlar/` EKLENDİ. SEBEBİ ÖNEMLİ:
#    8 Ağu'da AI-readiness için "makine-okunur API" yazıldı (`/api/ilanlar/[id]`,
#    hassas veri yok, 5 dk CDN cache) — AMA `Disallow: /api/` onu DÖRT BLOKTA DA
#    kapatıyordu. Yani uç, tam olarak kendisi için yazıldığı GPTBot/ClaudeBot'a
#    kapalıydı; üstelik siteden ona giden hiçbir bağlantı da yok. Ölü uçtu.
#    ⚙️ NASIL ÇALIŞIR: Google'da en UZUN (en spesifik) eşleşen kural kazanır.
#       `/api/ilanlar/` (13 karakter) > `/api/` (5 karakter) → Allow kazanır,
#       `/api/` altındaki HER ŞEY kapalı kalır. Bu yüzden `Disallow: /api/`
#       satırları olduğu gibi duruyor — kaldırılmadı, daraltıldı.
#    ⚠️ Yalnız `/api/ilanlar/` açıldı. Başka bir `/api/` yolunu açmadan önce o
#       ucun yanıtında hassas alan olmadığını DOĞRULA (`contact_phone`, `user_id`,
#       TCKN/VKN). `/api/ilanlar/[id]` bunları bilinçli olarak döndürmüyor.
#
# 🚨🚨 10 AĞU 2026 — `Disallow: /giris` KALDIRILDI. SAKIN GERİ EKLEME.
#
#    `noindex` ÇALIŞMASI İÇİN SAYFANIN TARANABİLİR OLMASI ŞARTTIR. Buradaki
#    yasak, `app/giris/layout.tsx`teki `robots: { index: false }` etiketini
#    OKUNAMAZ hâle getiriyordu: Google sayfayı çekemediği için "indeksleme"
#    talimatını hiç görmüyor, URL'i yalnız "engellendi" diye kaydediyordu.
#    İki talimat birbirini yok ediyordu ve NET ETKİ, hiçbirinin çalışmaması.
#
#    SAHADA GÖRÜLEN SONUÇ: Search Console 8 Ağu'da "Robots.txt tarafından
#    engellendi" bildirimi gönderdi; `/giris?redirect=/ilan/<id>` her ilan
#    sayfasında bağlantılı olduğu için on binlerce URL bu duruma düştü ve
#    "Düzeltmeyi doğrula" SONSUZA KADAR "beklemede" kalıyordu — kalmak zorundaydı,
#    çünkü doğrulamanın beklediği şey URL'in taranabilir olmasıydı.
#
#    DOĞRU KURULUM (şu an yürürlükte, üç katman ve her biri farklı iş yapıyor):
#      1. `rel="nofollow"`  → keşfi baştan engeller  (ilan sayfasındaki bağlantı)
#      2. taranabilir olmak → `noindex` etiketinin OKUNMASINI sağlar  (bu dosya)
#      3. `noindex`         → indeksten gerçekten düşürür  (giris/layout.tsx)
#    Yasak bunların yerine geçmez; 2. adımı bozarak 3.'yü de öldürüyordu.
#
#    ⚠️ AYNI ÇAKIŞMA `/admin/`, `/panel/`, `/moderator/`, `/araclarim/`,
#       `/profil-tamamla/`, `/auth/` yollarında da var (hepsi noindex + Disallow).
#       ORADA BİLİNÇLİ BIRAKILDI: bu yüzeyler auth arkasında ve herkese açık
#       hiçbir sayfadan bağlantılı değil, yani Google onları keşfetmiyor → rapor
#       gürültüsü üretmiyorlar. Yasak orada "taranmasın bile" demek; savunma
#       katmanı olarak kalıyor. Fark eden şey PUBLIC BAĞLANTI varlığı.
#       Bekçi: `npm run test:seo`.
